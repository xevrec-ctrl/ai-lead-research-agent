# AI 客户线索研究与方案决策 Agent：项目边界

## 业务问题

小型 AI 服务团队收到潜在客户线索后，通常需要人工搜索企业资料、判断需求、设计方案并安排跟进。资料来源分散，判断依据难以追溯，也容易漏掉后续动作。

本项目将这条流程做成一个可审核的 Agent 工作流：输入企业和需求，系统完成调研、证据筛选、机会判断、方案建议和任务草稿；所有外部写操作必须经人工确认。

## 最终工作流

1. 调研规划：识别已有信息和缺失信息，生成调研计划。
2. 并行调研：分别研究企业、行业、经营信号和近期动态。
3. 资料治理：去重、相关性筛选、来源保留和正文补全。
4. 机会分析：提取客户痛点，给出匹配度、价值、紧迫性、实施难度和风险评分。
5. 方案生成：为高优先级问题提出可落地的 Agent 方案、所需数据、工具和人工审批点。
6. 质量审核：逐项核对事实与来源；证据不足时退回补充调研。
7. 人工确认：用户批准、修改或拒绝建议方案和后续动作。
8. 业务落库：保存客户、报告和审批记录，并按需创建飞书待办。
9. 评测：统计结构完整率、引用有效率、工具调用成功率、延迟和模型成本。

## Agent 与普通模块的边界

Agent 负责需要模型判断和动态决策的工作：任务规划、搜索策略、需求分析、方案设计和质量审核。

普通代码负责确定性操作：评分公式、数据库读写、飞书 API、文件导出、权限检查和指标计算。项目不会把每个函数包装成 Agent 来制造复杂度。

## 简历准入条件

只有同时满足以下条件后才写入简历：

- 使用通义千问跑通完整流程；
- 至少完成 3 个可重复演示的企业案例；
- 外部写操作具备人工审批；
- 重要事实可以追溯到来源；
- 不少于 30 条评测样本有可复现结果；
- 自动化测试、启动文档、架构图和演示视频齐全；
- README 明确说明上游来源和本人完成的改造。

未达到这些条件前，本项目只算开发中的学习项目，不能按完整成果投递。
